# Alinear una tarea

Usa el contexto ya disponible: pedido del usuario, instrucciones y README del proyecto dueño, contratos, código y decisiones previas relevantes. No vuelvas a preguntar lo que esos materiales ya resuelven. Las tareas pequeñas y claras siguen el flujo directo del Harness.

Identifica solo las decisiones cuya ambigüedad pueda cambiar el resultado, el alcance, los datos o los efectos externos. Avanza con trabajo independiente mientras esperas una respuesta necesaria. Reúne las preguntas relacionadas en un grupo breve y formula opciones concretas cuando ayuden a decidir.

Resume la especificación con: problema y resultado esperado; alcance y fuera de alcance; supuestos confirmados y pendientes; comportamiento observable y condición de cierre; riesgos y dependencias. Usa el vocabulario del proyecto. Registra un término en su glosario si existe y su significado fue acordado; crea un ADR solo para una decisión duradera con una alternativa real y una razón verificable, en la ubicación del proyecto dueño.

La especificación orienta el trabajo; no amplía permisos ni autoriza acciones externas. Si el usuario ya pidió implementar y las decisiones esenciales están resueltas, entrega la especificación como parte del trabajo y continúa.
